\begin{abstract}
Tool-using agents built on large language models (LLMs) can be manipulated through instructions embedded in tool output or tool descriptions. As tools move into email, calendars, databases, and programming languages, this risk will continue to grow. Existing defenses modify the model itself, add a judge call after each agent action, or require a user to hand-author a policy for each tool. These methods do not scale well and do not provide complete protection. IntentGate is a lightweight middleware gate that extracts an intent contract directly from the user's trusted request before any malicious content is added. Each tool call is evaluated by its similarity to the extracted contract and a simple rule-based veto. Based on this evaluation, the call is allowed, blocked, or escalated to human review. This is done without requiring a direct LLM call for every action taken by the agent. The location of IntentGate provides a single point at which all tool calls occur, so the required policy comes from the user rather than from any content provided by an attacker. Evaluation was performed on two attack types: indirect injection on 2{,}108 InjecAgent cases and tool poisoning on 1{,}348 MCPTox cases. Under static attacks, attack success on InjecAgent falls from 19.0\% to 0.7\%, and attack-influenced MCPTox tool calls fall from 20.7\% to 10.7\%. Both benchmarks show large reductions. The gate adds 16--20 ms p95 CPU latency and needs no hand-authored per-tool contracts, compared with 145 for the ToolGate baseline. Additional testing on a second backbone (qwen3.5:4b) produced a comparable ASR reduction on InjecAgent (27.1\% to 2.1\%). The evaluation of benign utility, prompt baselines, and adaptive probes remains preliminary.
\end{abstract}

\section{Introduction}

LLM agents that use tools have access to the user's environment, including email, calendars, databases, and code, through a continuous cycle similar to ReAct~\cite{yao2023react}. At the same time, this access is also the attack surface. An attacker could send instructions via an email attachment, calendar invitation, database entry, or tool output, which are examples of indirect prompt injection~\cite{greshake2023notwhat,perez2022ignore}. A malicious tool description in the Model Context Protocol (MCP) could direct the agent through tool poisoning, described on actual MCP servers~\cite{wang2026mcptox,radosevich2025mcp}. In either case the agent acts on the attacker's instruction without user authorization, which is the excessive-agency risk in the OWASP Top 10 for LLM applications~\cite{owasp2025llmtop10}. A recent survey catalogues attack techniques across agent workflows and protocol layers~\cite{ferrag2026survey}. Current defenses modify the model, make a judge call on the input, or require a hand-authored tool policy before execution, and a few derive the policy directly from the task~\cite{shi2025progent}. IntentGate is a middleware gate that evaluates each tool call against an intent contract extracted from the trusted user request. It is evaluated on InjecAgent for indirect injection and MCPTox for tool poisoning.

Prior defenses differ in where they enforce control. Model-based defenses alter the model or its training data. CaMeL wraps the model in a planner-executor architecture with capability tracking~\cite{debenedetti2025camel}. StruQ fine-tunes the model to separate task instructions from data~\cite{chen2025struq}. SecAlign applies preference optimization to the same end~\cite{chen2025secalign}. Instruction-hierarchy training teaches models to prioritize trusted instructions~\cite{wallace2024instruction}. These methods assume model cooperation, and none has a head-to-head evaluation on InjecAgent or MCPTox. Data-level defenses identify or block untrusted text. Spotlighting transforms it into a marked form~\cite{hines2024defending}. Toolkits such as NeMo Guardrails enforce programmable rails, but the model still decides whether they apply~\cite{rebedea2023nemo}.

The open question is whether a gate that scores each tool call against a contract from a single trusted request can reduce attacks on both benchmark classes. On InjecAgent, attack success fell from 19.0\% to 0.7\%, and on MCPTox attack-influenced tool calls fell from 20.7\% to 10.7\%. The gate adds 16--20 ms p95 CPU latency and needs no hand-authored per-tool contracts. On MCPTox, a ToolGate reimplementation with 145 contracts is statistically indistinguishable from the unprotected agent.

\section{Background and Related Work}

\subsection{Threat model}
This threat model is a tool-using LLM agent in a ReAct-style loop~\cite{yao2023react}. Based upon a trusted user request, the agent proposes potential tool calls, then runs those calls, receives output, and continues running calls until there is a result provided to the user. The attacker may introduce malicious content either through tool descriptions (tool poisoning) or through retrieved or returned content (indirect injection). Additionally, tool-selection attacks allow the agent to select a registered attacker tool even when the user's task is benign~\cite{shi2025toolhijacker}. The attacker's goal is to make the agent execute an unauthorized tool call (data exfiltration, message sending, state changes, or credential exposure). The defender's goal is to block or escalate unauthorized tool calls without disrupting legitimate task completion. Everything following the initial request (tool definitions returned by a registry, tool outputs, injected document text) is potentially attacker-controlled. Attack content includes manually written text as well as optimized sequences~\cite{zou2023universal}, and earlier studies describe related failure modes in emulated agent environments~\cite{ruan2024identifying}.

\subsection{Defenses}
Model-level defenses track information flow at the model or runtime level. CaMeL~\cite{debenedetti2025camel} uses a planner-executor approach with capability-based taint tracking, so data from attacker-controlled sources cannot reach tool arguments. StruQ~\cite{chen2025struq} fine-tunes the model to separate instructions from data with structured queries, and SecAlign~\cite{chen2025secalign} applies preference optimization to the same end. Instruction-hierarchy training~\cite{wallace2024instruction} teaches the model to prioritize privileged instructions. All of these require model cooperation, and none has a head-to-head adversarial evaluation on InjecAgent or MCPTox. Data-level defenses mark or transform untrusted text. Spotlighting~\cite{hines2024defending} transforms retrieved content into clearly delimited forms. Guardrail toolkits such as NeMo Guardrails~\cite{rebedea2023nemo} enforce programmable rails around the model, but the model still makes the final call. Detection methods add training or inference cost: BIPIA fine-tunes a detector alongside its benchmark~\cite{yi2025benchmarking}, and MELON re-executes with masked tools and compares outputs~\cite{zhu2025melon}.

Judge-based defenses query a second language model to review each proposed call~\cite{taskshield2025}. They are flexible, but they add cost and latency with a language-model call on every action. They also create a new attack surface, because the judge can be prompt-injected, and produce implicit policies that are hard to audit. Contract-based defenses come closest to where this work enforces control. ToolGate~\cite{liu2026toolgate} enforces preconditions and postconditions for each tool at the tool-call boundary through hand-authored \emph{per-tool contracts}. In this reimplementation the policy source is the weakness. Coverage is incomplete (65/801 MCPTox tools, 8.1\% distinct and 37.2\% availability-weighted), and attacker-registered tools have no contract. Progent version 3~\cite{shi2025progent} derives its initial symbolic policy from the user's task and updates it during execution. A solver-based check (SMT) permits narrowing automatically and requires approval for expansion. Its call check is symbolic, while IntentGate freezes its contract and uses embedding scores plus vetoes. ClawGuard~\cite{clawguard2026} derives task-specific constraints from the user-specified objective and enforces them deterministically, with a user confirmation step. It reports results on InjecAgent and MCPTox, so this paper does not claim to be the first to derive policy from the request. Prompt Flow Integrity~\cite{kim2025promptflow} prevents privilege escalation through agent isolation and data tracking, and it is evaluated on AgentDojo and AgentBench. TrustAgent~\cite{hua2024trustagent} uses a hand-authored constitution and is evaluated by emulation, not live tool execution. A recent design-pattern survey~\cite{beurerkellner2025design} argues that the safest agent designs never let untrusted data steer privileged actions, which supports the gate placement used in this study.

AgentDojo~\cite{debenedetti2024agentdojo}, InjecAgent~\cite{zhan2024injecagent}, and Agent Security Bench~\cite{zhang2025asb} provide the injection benchmarks. MCPTox~\cite{wang2026mcptox} provides the tool-poisoning benchmark, and the MCP specification itself ships no defense against poisoned registrations~\cite{anthropic2024mcp,radosevich2025mcp}. Zhan et al.~\cite{zhan2025adaptive} show that adaptive attackers break defenses that look strong under static attacks. The primary claims are therefore scoped to static attacks, and an offline adaptive-attacker probe is reported as preliminary.

\subsection{Research gap}
ToolGate needs a hand-authored contract for every tool. Progent derives a symbolic policy and updates it during execution. ClawGuard derives task-scoped constraints from the user's objective and asks the user to confirm them. Task Shield adds a language-model judge on every action. IntentGate parses the trusted request once into a frozen contract and enforces it with a CPU embedding score plus a deterministic veto. It needs no model change, no retraining, no per-action LLM, and no per-tool authoring. The measured contribution is a direct comparison with a ToolGate reimplementation on an injection benchmark and on the covered subset of a tool-poisoning benchmark. The setup cost is measured directly: 145 contracts for the ToolGate baseline versus 0 for IntentGate.

\section{Method}

\subsection{System overview and ordering invariant}
IntentGate sits between the agent and the executor. Figure~\ref{fig:gate} shows the pipeline. The ordering invariant is strict. The intent contract is parsed from the trusted user request \emph{before} tool definitions or any attacker content (injected observations, poisoned tool descriptions) are assembled. Tool outputs are never passed to the parser. Every proposed tool call, user-initiated and attacker-influenced alike, passes through \texttt{GateMiddleware.execute()} with no bypass path.

\subsection{Intent parser and contract schema}
A trusted intent parser (an LLM at temperature 0, JSON mode, one repair retry) reads the user request once per session and emits an intent contract, the request-derived policy used by the gate
\begin{equation}
C = (A, K, H), \label{eq:contract}
\end{equation}
In this contract, $A$ is the set of allowed (entity, operation, resource) elements, $K$ is a set of numeric and path constraints, and $H$ is a set of high-risk flags. The implementation realizes $A$ as the contract's goals, expected tool categories, and permitted data access, $K$ as argument constraints, and $H$ as side-effect limits. A call that touches an element outside $A$, violates a constraint in $K$, or matches a flag in $H$ fails the rule check and triggers the veto. The schema is versioned and frozen for the evaluation. The contract is embedded once per session and reused. Only the proposed call is embedded at decision time, which keeps the agent prompt cacheable and the gate out of the prompt.

\subsection{Scorer}
Each proposed tool call $c$ is scored against the contract. The semantic component maps the cosine similarity between the contract embedding $e_C$ and the call embedding $e_c$ to $[0,1]$:
\begin{equation}
S_{\mathrm{sem}} = \frac{1 + \cos(e_C, e_c)}{2} = \frac{1}{2}\left(1+\frac{e_C \cdot e_c}{\lVert e_C \rVert \, \lVert e_c \rVert}\right), \label{eq:sem}
\end{equation}
The rule component is deterministic: $S_{\mathrm{rule}} \in \{0,1\}$. It is 1 when $c$ passes all constraints in $K$ and 0 when the veto fires. The combined score is
\begin{equation}
S = \alpha \, S_{\mathrm{sem}} + (1 - \alpha) \, S_{\mathrm{rule}}, \label{eq:score}
\end{equation}
A veto sets $S=0$ before thresholding. The default is $\alpha = 0.7$. The threshold $\tau = 0.75$ and half-width $\delta = 0.1$ were fixed on a 50-call pilot before any benchmark run. The study reports the operating point and does not claim that the choice is optimal or that it transfers across splits.

\subsection{Gate middleware and escalate band}
The middleware decides per call:
\begin{equation}
\mathrm{decision}(c) =
\begin{cases}
\text{\textsc{block}}, & S_{\mathrm{rule}}=0 \ \text{or}\ S < \tau-\delta, \\
\text{\textsc{escalate}}, & S_{\mathrm{rule}}=1 \ \text{and}\ \tau-\delta \le S < \tau, \\
\text{\textsc{allow}}, & \text{otherwise},
\end{cases} \label{eq:decision}
\end{equation}
The block case is fail-closed. The escalate case routes to human review, is counted as a block in benchmark mode, and is shown to the user in demo mode. Algorithm~\ref{alg:gate} lists the full procedure. Of the 583 escalated calls, 60.7\% target attacker tools, 14.8\% target user tools, and 24.5\% target other tools. The gate adds no LLM call per action. Measured p95 per-call latency is 16--20 ms on CPU.

\begin{algorithm}[t]
\caption{Gate decision for one proposed tool call}
\label{alg:gate}
\footnotesize
\begin{algorithmic}[1]
\Require contract $C=(A,K,H)$ with embedding $e_C$; tool call $c$ with embedding $e_c$; parameters $\alpha,\tau,\delta$
\Ensure decision $d$: allow, block, or escalate
\State $S_{\mathrm{sem}} \gets \frac{1 + \cos(e_C, e_c)}{2}$
\State $S_{\mathrm{rule}} \gets 1$ if $c$ satisfies $A$ and $K$, else $0$
\State $S \gets \alpha S_{\mathrm{sem}} + (1-\alpha) S_{\mathrm{rule}}$
\If{$S_{\mathrm{rule}}=0$ or $S < \tau-\delta$}
  \State $d \gets \mathrm{block}$ \Comment{fail-closed hard veto}
\ElsIf{$S < \tau$}
  \State $d \gets \mathrm{escalate}$ \Comment{human-review band}
\Else
  \State $d \gets \mathrm{allow}$
\EndIf
\State \Return $d$
\end{algorithmic}
\end{algorithm}

\section{ToolGate Baseline (B2)}

The primary baseline is a minimal reimplementation of ToolGate~\cite{liu2026toolgate}: contracts with preconditions $P$ and postconditions $Q$ over a symbolic world state, plus snapshot and rollback when a postcondition fails. Contracts cover the evaluated tool subset only: InjecAgent 79/79 user and attacker tools (100\%), MCPTox 65/801 registered tools (8.1\% distinct and 37.2\% availability-weighted). Missing contracts are never silently allowed: they are counted as \texttt{no\_contract} and reported. Fidelity was validated by contract review and recorded-call replay instead of a ToolBench run.

Setup cost is measured directly: ToolGate requires 145 hand-authored contracts on InjecAgent, compared with zero hand-authored contracts for IntentGate, whose contract is derived from the request. On MCPTox, extending contracts toward 84.9\% weighted coverage leaves attack success flat, because attack calls look like legitimate queries. The attack is in the poisoned registration, so the tool call itself looks legitimate. ToolGate is statistically indistinguishable from the unprotected baseline on MCPTox, which supports the direct comparison.

\section{Evaluation}

\subsection{Benchmarks and cases}
\textbf{InjecAgent}~\cite{zhan2024injecagent}: indirect prompt injection in tool-integrated agents, 2,108 cases (direct-harm and data-stealing attacker intents, in base and enhanced settings), frozen at pinned commits. \textbf{MCPTox}~\cite{wang2026mcptox}: tool poisoning on real-world MCP servers, 1,348 static-snapshot cases. MCPTox results are explicitly scoped to the static snapshot (live-server evaluation is deferred, and the poisoning-at-registration logic is identical in both).

\subsection{Metrics}
Attack success rate (ASR): share of attack cases where the attacker's objective is achieved. For MCPTox, the same quantity is reported as attack-influenced calls because the heuristic evaluator flags payload or sensitive-path evidence rather than a strict objective. Block rate: share of gated calls blocked or escalated, reported by stratum where stratified. Valid rate: share of user-tool calls the gate allows, a call-level utility proxy. Latency: p50/p95 per-call gate overhead. Setup cost: hand-authored contracts required.

\subsection{Baselines and ablations}
B1 is the unprotected agent. B2 is the ToolGate reimplementation. IntentGate uses $\tau=0.75$, $\delta=0.1$, and $\alpha=0.7$. The full matrix adds three ablations: A1 semantic-only (no rule veto), A2 rule-only (no embeddings), A3 raw-request embedding (similarity to the request text instead of the parsed contract). All conditions run with identical prompts, tool blocks, agent model (gpt-4o-mini), embedding model (all-MiniLM-L6-v2~\cite{reimers2019sentence}), and seed 42.

\subsection{Statistics}
All comparisons use the paired McNemar test with continuity correction~\cite{dietterich1998approximate}. Confidence intervals come from a seeded bootstrap with 10k resamples for each benchmark and risk breakdown. The 10 risk breakdowns use Bonferroni correction ($\alpha=0.005$). Post-hoc power is 1.0 at $\alpha=0.005$ for both benchmarks. Results from the full matrix are reported as-is. Pilot results are labeled preliminary.

\section{Results}

\subsection{Main results}
Table~\ref{tab:headline} and Figure~\ref{fig:bars} summarize the headline result. On InjecAgent, IntentGate reduces ASR from 19.0\% to 0.7\%. On MCPTox, it reduces attack-influenced calls from 20.7\% to 10.7\%. On the primary slices (the enhanced data-stealing portion of InjecAgent and the full MCPTox snapshot), McNemar gives $p=1.3\mathrm{e}{-}33$ and $p=1.25\mathrm{e}{-}07$. The ToolGate baseline reduces ASR by 1.8 percentage points (17.2\% vs.\ 19.0\%) on InjecAgent and is not statistically distinguishable from the unprotected agent on MCPTox. Call-level utility is reported with the benign-task pilot in Section~\ref{sec:validation}.

\subsection{Setup cost}
IntentGate requires zero hand-authored contracts. ToolGate requires 145 contracts on InjecAgent and 65 on MCPTox (full matrix). Extending the MCPTox set to 583 ToolGate contracts raised weighted coverage to 84.9\% without closing the gap. ToolGate's paper does not report this setup-cost metric.

\subsection{Ablations}
Semantic scoring alone reaches 0.0\% ASR on InjecAgent. The rule-only ablation (A2) is the weakest condition, with 14.7\% ASR on InjecAgent and 263 attack-influenced MCPTox calls, close to the unprotected agent on the hard slices. Semantic-only (A1) detects more than the full gate on MCPTox (81 vs.\ 144 attack-influenced calls) but over-blocks legitimate calls, as the benign-task pilot shows. The raw-request ablation (A3) matches the full gate on InjecAgent (0.7\% both) and catches slightly more attacks on MCPTox (116 vs.\ 144 attack-influenced calls). The contract's value is therefore utility and auditability. Headline ASR is similar. The false-escalate rate is 14.8\% over those 583 escalated calls.

\subsection{Error taxonomy}
Thirteen InjecAgent failures remain. All are read-only exfiltration calls with $S \in [0.75,0.79]$, just above $\tau$. All 13 were already allowed, and rewording them to sound like the user's request raised $S$ by 0.0112 on average without moving any additional case across $\tau$. These prose variants therefore do not change the operating point. The remaining MCPTox failures cluster in poisoned-registration cases whose calls look like legitimate queries, so no request-level rule fires.

\subsection{Validation results (preliminary)}
\label{sec:validation}
A second backbone, qwen3.5:4b, replicates the ASR reduction on InjecAgent (27.1\% $\rightarrow$ 2.1\%, $n=100$ per condition). gpt-6-luna is excluded because its prose-only output never participates in the ReAct-style loop. On 2,013 gated calls, the block rate is 12.8\% for specific contracts, 9.6\% for vague contracts, and 12.4\% overall.

The benign-task pilot (50 clean cases) compares the unprotected agent, the full gate, and the semantic-only ablation. User-tool allowed rates are 16.0\%, 12.0\%, and 8.0\%. Clean-call block rates are 0.0\%, 25.0\%, and 42.9\%. Semantic-only over-blocks legitimate calls, so the contract preserves more of them in this comparison.

The prompt-baseline pilot tests 50 attack cases per condition. ASR is 6.8\% with no defense prompt, 4.3\% with delimiters, 4.3\% with sandwiching, and 8.9\% with instructional prevention. DeepSeek V4.1 Flash refused the static injections (0/100 in both conditions), so its delta is undefined. This is a model-level refusal, not a gate effect. Phrasings that change how the injection is delivered stayed at or below 2.2\% gated ASR. All pilot numbers are preliminary.

\section{Limitations}

The primary claims are scoped to static attacks. Adaptive-attacker performance is not claimed. An offline probe that copies the user request into free-text tool arguments can inflate $S$ above $\tau$. In an offline replay, a six-token verbatim-echo guard blocks all 34 measured adaptive calls (11/11 call templates) with no new blocks among 194 allowed user-tool calls. The main results remain unchanged. MCPTox results are on a static snapshot, not live servers. The full matrix uses a single backbone (gpt-4o-mini). qwen3.5:4b replicates the delta, and gpt-6-luna is incompatible with the shared ReAct-style prompt. DeepSeek's refusal is a model boundary, not evidence of gate generality. The parser is an LLM call once per session, included in the cost. Per-action enforcement uses no LLM.

For the ToolGate baseline, contract coverage for MCPTox tools outside the evaluated subset remains low by design. Missing contracts are counted as \texttt{no\_contract} and never silently allowed. The valid rate measures call-level allowance of the user's tool call, not end-to-end task success. The benign-task pilot is a 50-case comparison and should be read as such. Block rate includes escalate candidates and is not a pure false-positive rate. The MCPTox attack-influenced metric comes from a heuristic evaluator (payload and sensitive-path evidence), which is coarser than a strict objective check.

\section{Conclusion}

The results show that an action gate can derive its policy automatically from the user's request and enforce it with embedding similarity plus a deterministic veto at the tool-call chokepoint. The gate needs no hand-authored per-tool contracts, adds 16--20 ms p95 latency, and reduces attack success on an injection and a tool-poisoning benchmark. The reproducible artifact is released after acceptance. Future work covers adaptive-attacker hardening, live-server MCPTox evaluation, and multi-turn drift.
